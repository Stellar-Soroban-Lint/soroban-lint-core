## When it fires

A value loaded from storage with `.get(..)` is grown with `push`, `insert`, `append`, or `extend` and then written back with `.set(..)`, with no visible length bound: no `if`/`match` guard comparing `.len()` against a constant or a limit, no early return on capacity, and no constant cap anywhere in the function.

Growth on a local that was never loaded from storage is not flagged, and neither is growth inside a loop bounded by a constant.

## Examples

Flagged — the collection is loaded, grown, and stored with no cap in sight:

```rust
#[contractimpl]
impl Pool {
    // warning: SL004, unbounded storage growth
    pub fn add(env: Env, who: Address, id: u32) {
        let mut items: Vec<u32> = env.storage().persistent().get(&Items).unwrap_or_default();
        items.push(id);
        env.storage().persistent().set(&Items, &items);
    }
}
```

Not flagged — an explicit bound before the growth:

```rust
let mut items: Vec<u32> = env.storage().persistent().get(&Items).unwrap_or_default();
if items.len() >= MAX_ITEMS {
    return Err(Error::Full);
}
items.push(id);
env.storage().persistent().set(&Items, &items);
```

## False positives and false negatives

**False positives.** A bound enforced by a caller or external configuration may be invisible to the rule, so valid growth can be reported.

**False negatives.** Growth methods, storage aliases, or bounds expressed in forms the visitor does not recognize can escape detection.

## Suppressing this rule

If the bound is genuinely enforced elsewhere — by a caller or by configuration the linter cannot see — suppress the specific line and say where the bound lives:

```rust
// soroban-lint-ignore: SL004 -- caller rejects past MAX_ITEMS
items.push(id);
```
