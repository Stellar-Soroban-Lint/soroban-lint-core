## When it fires

A `.temporary().set(key, value)` where the key or value identifier matches a balance/ownership heuristic: `balance`, `owner`, `allowance`, `admin`, `supply`, or `total`. Temporary storage is evicted aggressively, so balances or ownership held there can be silently lost or reset.

This is a naming heuristic and the weakest rule in the set. Genuinely ephemeral data whose identifiers happen to match will be flagged, and mis-typed data under an innocuous name will be missed.

## Examples

Flagged:

```rust
// warning: SL006, `balance` in temporary storage
env.storage().temporary().set(&balance_key, &amount);
```

Not flagged — persistent storage for the same data:

```rust
env.storage().persistent().set(&balance_key, &amount);
```

## False positives and false negatives

**False positives.** Ephemeral data named `balance`, `owner`, `allowance`, `admin`, `supply`, or `total` can match the naming heuristic.

**False negatives.** Important balance or ownership data under an innocuous identifier does not match the heuristic.

## Suppressing this rule

If the name is a false alarm — a `total` that really is a per-invocation counter, for instance — suppress it and keep the rule on for the rest of the crate:

```rust
// soroban-lint-ignore: SL006 -- per-invocation counter, not a balance
env.storage().temporary().set(&total_key, &n);
```

0 findings on the pinned corpus. That is not evidence the rule is precise; with no hits there was nothing to triage, which is one of the reasons promotion is deferred.
