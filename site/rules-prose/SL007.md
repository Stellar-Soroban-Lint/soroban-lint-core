## When it fires

A contract function named `init`, `initialize`, or `__init`, or carrying a `#[constructor]`-style role attribute, writes an `initialized`- or `admin`-like storage key and has neither an already-initialized guard nor an auth call.

Soroban's native `__constructor` is never flagged — it runs once at deployment. Functions that write no initialization state are also not flagged.

## Examples

Flagged:

```rust
#[contractimpl]
impl Contract {
    // warning: SL007, initializer with no guard and no auth
    pub fn initialize(env: Env, admin: Address) {
        env.storage().instance().set(&Admin, &admin);
    }
}
```

Not flagged — a guard plus auth:

```rust
pub fn initialize(env: Env, admin: Address) -> Result<(), Error> {
    if env.storage().instance().has(&Admin) {
        return Err(Error::AlreadyInitialized);
    }
    admin.require_auth();
    env.storage().instance().set(&Admin, &admin);
    Ok(())
}
```

## False positives and false negatives

**False positives.** A safe initializer whose one-time guarantee is enforced externally may still match if the guard and auth are not visible.

**False negatives.** Initializer functions with different names or storage keys outside the syntactic name patterns may not be recognized.

## Suppressing this rule

If your initializer is reachable exactly once by construction and you would rather keep it short, name the rule and record the reasoning:

```rust
// soroban-lint-ignore: SL007 -- only reachable from __constructor
pub fn initialize(env: Env, admin: Address) { /* ... */ }
```
